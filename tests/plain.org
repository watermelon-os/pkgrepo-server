* Описание тесткейсов в стиле BDD свободным текстом

* Сервер

- Бд не подключена.
  - Любой запрос, требующий обращения к БД, возвращает ошибку.

- Каждый запрос(команда) получает id
  - id короткий и уникальный
  - Каждая операция от инициализации до завершения передает id
  - Логи содержат id запроса
  - url запуска процесса поддерживает шаблонизатор, id передается через url
  - url колбэка также содержит id, оркестратор передает в него отчёт

    
** Работа с пакетами

- Обращение к несуществующему пакеты.
  - Ошибка.


*** Добавление пакет

- пакет существует той же версии
  - ошибка

- В бд нет пакета с таким именем или версией.
 - Функция добавления вызвана.
 - Теперь в бд есть запись, статус соответствует тому что указан и тип репозитория с пакетной системой и остальным, так же соответствует.


*** Обновление пакета

- В репозитории есть пакет, ровно с теми же параметрами, но отличается хэшсумма.
 - Вызов функции. 
 - В фс пакет перезаписался.
 - Варнинг.

- Вызов функции добавления, с параметрами аналогичными, хэшсумма просчиталась аналогичной. 
  - Ошибка. 

     
*** Тестирование пакета

- привязка к версии пакета

- Вызов функции
  - пакет получил запись о начале тестирования

- пакет содержит журнал запусков тестирования
  - статус верификации — вычисляемое значение по последнему завершенному тестированию, а не хранимое
  - за изменением журнала следует изменение статуса
  - статус всегда актуален и опирается на результаты процессов 

- тестирование можно  помечать недействительным
  - оно не влияет на статус пакета

- Для пакета не установлен url на запуск запрос теста
  - использовать общий url если настроен
  - url не настроен
    - ошибка

	
*** Сборка пакета

- нет привязки к версии
  
- аналогично тестированию, за исключением переменных
  - свой журнал сборки
  - свои url
  - свой вычисляемый статус сборки по последней завершенной, а не хранимое значение


*** Перемещение пакетов между репозиториями 

- Пакеты связаны с репозиториями, то есть с директориями в файловой системе, уже проинициализированными как репозитории (rpm, deb и т.д.)

- когда репозитория не существует
  - попытка переместить в него вернет ошибку

- перемещение в другой репозиторий, это операция обновления пакета, с указанием репозиториев которые должны его содержать

- вызов обновления с попыткой установить новый список как пустой
  - вернет ошибку

 

*** Найти пакет

- поиск принимает
  - название пакета
  - версию
  - репозиторий
  - вычисленные статусы из журналов процессов

- результат поиска возвращает полную информацию о найденных пакетах

** Работа с оркестраторами процессов

- пакет может и вовсе не включать ни какие процессы
 - в таком случе вызовы протестировать или собрать пакет вернут ошибку
   - так как процесс для данного пакетане настроен

** Настройка сервера

- задаются через env/cli

- нельзя изменить пока запущен сервер

#+begin_comment
- настройки представляются в json формате

- сервер можно заставить пречитать настройки
  - в таком случае он сначала провалидирует эти настройки
    - может вернуть ошибку
  - тогда попытка прочитать эти настройки уже вернет новую

- можно установить определенные праметра, а не целиком
  - тогда обновление праметр
    - может вернуть ошибку
    - или мгновенно примениться
#+end_comment
